# Glossary (Quick Reference)

This document lists the most frequently used terms. For the complete canonical glossary, see [`/knowledge/11_GLOSSARY.md`](/knowledge/11_GLOSSARY.md).

| Term | Definition |
|---|---|
| **Architecture** | The layered organization of the platform that separates concerns through a deterministic hierarchy. |
| **Baseline** | The set of accepted architectural components and decisions forming the permanent foundation. |
| **Component** | A logical unit with clear ownership boundaries contributing to platform functionality. |
| **Module** | A self-contained unit of business functionality conforming to the module contract. |
| **Infrastructure** | Internal platform services (orchestration, lifecycle, events, persistence, diagnostics). |
| **Public API** | Stable contract enabling modules to access infrastructure without implementation exposure. |
| **Capability** | A declarative statement of what the platform or a module can do. |
| **Service** | A reusable implementation fulfilling a capability contract. |
| **Dependency** | A declared relationship requiring a specific capability or service. |
| **EPIC** | An Architectural Enhancement Proposal representing a unit of change. |
| **VERIFIED** | Conclusion supported by direct, objective evidence. |
| **EXPECTED** | Logical inference from verified facts, not directly observed. |
| **UNKNOWN** | Insufficient evidence to draw a conclusion. |
| **Evidence** | Verifiable output used to support a claim. |
