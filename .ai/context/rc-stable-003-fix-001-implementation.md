# RC-STABLE-003-FIX-001 Implementation Report

## 1. Objective

Fix `Target collection not found in profile.` for real GoldenBride profiles by
supporting **array** message collections (`unknown[]`) at the canonical
IceBreaker/Broadcast paths alongside the existing keyed-object shape
(`Record<string, unknown>`), while preserving all RC-STABLE-003 replacement
semantics: shape-preserving rebuild, deterministic ordering/IDs, delay
preservation, no-change detection, count-aware confirmation (including
shape-change during confirmation), single verified write with canonical
rollback, and import history. The temporary FIX-001A diagnostic is removed.

- `readDelays()` and the detection helpers (`detectTextProperty`,

  items via `Object.values()` / `DELAY_PROPERTIES`, so arrays were already

## 5. Root Cause (VERIFIED)

Real diagnostic payload for profile `chat-sender-1373302`
(`phase:"initial"`, `profileFound/profileRead/profileValid` all `true`,
`resolved:false`, `resolutionPath:null`):

- Candidate `data.messages`: `containerType:"array"`, reason
  `"array container (not a message object)"`.
- Broadcast: `data.broadcast` is an object (keys `type, status, message,
  messages, specified`); candidate `data.broadcast.messages`:
  `containerType:"array"`, same array rejection.
- `profileShape.topLevel` captures `messages:"array"`,
  `broadcast:"object"`, `advanced:"boolean"`, `chainProgress:"object"`.

Conclusion: the canonical paths are correct; the failure is a
**container-shape compatibility issue** — `getTargetMessages()` accepted only
keyed objects and rejected arrays. No path-layout change is required; the
implementation must accept both shapes.

## 8. Changes Per File

### `src/companion/crm-service.ts`
- **Added** `type MessageCollection = Record<string, unknown> | unknown[]` with a
  doc comment: keyed object (RC-STABLE-003 canonical) or array (confirmed real
  GoldenBride container shape); no other container types or paths supported.
- **Removed** the FIX-001A temporary diagnostic completely:
  `logImportResolutionDiagnostic`, `buildImportResolutionDiagnostic`,
  `describeProfileShape`, the initial-read call site, the post-confirmation call
  site, and the `[RC-STABLE-003-FIX-001]` prefix.
- **`getTargetMessages`** now returns `MessageCollection | undefined` via a new
  `isMessageCollection(value)` type guard (`!!value && typeof value ===
  "object"` — accepts plain objects and arrays, rejects null/primitives/functions).
- **Added** `collectionCount(messages)`: array `.length`, object
  `Object.keys().length`; used for `previousMessageCount` and
  `finalMessageCount`.
- **`buildReplacementMessages`** preserves the source shape: array sources yield
  a dense array (index 0 = Message 1, no sparse entries, no string-key
  metadata); object sources yield keys exactly `"1".."N"` (no zero-based keys,
  no old IDs/gaps). Items carry only the detected text property + delay property
  (canonical default `intervalSeconds`), first delay `0`, later delays the
  detected value. No runtime/progress fields copied. Rebuilt items carry only
  confirmed `text` and delay property — no extra fields from old elements.
- **`canonicalSnapshot`** now returns `{ shape: "array"|"object",
  textProperty, delayProperty, items: [{ text, delay }] }`: shape discriminator +
  canonical property names + ordered text/delay only (never identity, insertion
  order, or runtime fields). Object entries are ordered by numeric key; array
  entries by index.
- **`messagesEquivalent`** compares the full snapshot JSON — arrays and objects
  with identical text/delay are **not** equivalent (shape discriminator).
- **`deepCopyCollection`** returns `MessageCollection` via JSON round-trip
  (limitation documented: plain data only, functions/symbols dropped).
- **`verifyReplacement`** accepts `expected: MessageCollection`; equivalence via
  the shape-aware snapshot.
- **`rollbackTargetCollection(key, target, originalCollection,
  originalSnapshot)`**: immutable `originalCollection` + canonical
  `originalSnapshot` captured before mutation; after restore, verifies the
  target resolves AND the canonical snapshot equals `originalSnapshot` (shape +
  content; count-only checks removed). Never derives expectations from mutated
  refs.
- **Widened** params (behavior unchanged, `Object.values()` already handles
  arrays): `detectTextProperty(messages: MessageCollection | undefined)`,
  `detectDelayProperty(messages: MessageCollection | undefined)`,
  `applyPropertyUpdates(messages: MessageCollection | undefined, ...)`.
- `importSnippetsToProfile` flow otherwise unchanged (fresh read → count →
  optional confirm → fresh re-read → delay detection → rebuild → canonical
  no-change compare → one write → read-back verification → rollback on failure
  → history).

## 9. Container Shape Semantics

- Supported containers at `data.messages` and `data.broadcast.messages`:
  non-null plain object or array (including empty). Rejected:
  missing/undefined, null, strings, numbers, functions.
- The container is never auto-created; missing/invalid containers fail with the
  existing `Target collection not found in profile.` message (unchanged).
- Empty array/object: resolves, imports with defaults (delay fallback
  `DEFAULT_DELAY = 65`), and the rebuilt collection preserves the empty shape
  (array stays array, object stays object).

## 10. Array Replacement Semantics

- Dense output: `index 0` = Message 1; length equals unique-snippet count.
- No sparse entries; no string-key metadata on the array; pasted order
  preserved; omitted messages removed; duplicates within the paste skipped.
- `previousMessageCount`/`finalMessageCount` derived from array length.
- First element delay `0`; later elements use the detected delay.

## 11. Object Replacement Semantics

- Output keys exactly `"1".."N"`; no zero-based key; no old IDs/gaps; pasted
  order preserved; canonical `{ text, intervalSeconds }` schema.
- No runtime/progress fields copied.

## 12. Canonical Snapshot and Equivalence

- Snapshot = `{ shape, textProperty, delayProperty, items }` where `items` is
  the ordered `{ text, delay }` list under the resolved canonical property
  names (`detectDelayProperty ?? "intervalSeconds"`).
- Used for no-change compare, write verification, and rollback confirmation.
- Arrays and objects with identical text/delay are NOT equivalent; insertion
  order is irrelevant (numeric-key ordering for objects).

## 13. Delay and Text Detection

- `detectTextProperty` returns the first string key that is not a delay-ish
  name, defaulting to `"text"`.
- `detectDelayProperty` matches `DELAY_PROPERTIES` on the first item,
  defaulting to `"intervalSeconds"`.
- Both accept arrays/objects (item iteration via `Object.values`). Widen only —
  no behavior change.
- `readDelays` (target-specific `priv`/`broad`) unchanged and array-safe.

## 14. No-Change Detection

- A re-import whose canonical snapshot equals the current collection is
  `no-change`: zero writes, `no-change` history (`importedCount: 0`). Same-shape
  identical content for both arrays and objects.

## 15. Confirmation Workflow

- Count-aware confirmation invoked only when the target already has messages;
  empty collections skip it. Cancel → `cancelled`, no write, no history.
- **Latest-shape rule**: after confirmation the profile is re-read fresh; if the
  collection changed shape during confirmation (object→array or array→object),
  the rebuild follows the **latest** shape. (Harness M33/M34 verify both
  directions.)

## 16. Storage Safety and Rollback

- Immutable `originalCollection` (JSON deep copy) + `originalSnapshot` captured
  before mutation.
- One `writeProfile` for success; read-back verification = validate + target
  resolves + canonical snapshot equals rebuilt.
- On verification failure, rollback writes the original collection back and
  re-verifies canonical snapshot equality with the original (shape + content,
  not just count). Honest reporting: "original messages were restored" vs
  "manual recovery is required" when rollback verification itself fails
  (harness M42 double-corrupt path).
- Write counting: success = 1; verify-failure = 2 (intended + rollback);
  no-change/failure/cancel = 0.

## 17. Import History

- Unchanged from RC-STABLE-003: static `addImportHistory`, `success` /
  `no-change` / `failed`, nothing on cancel, `importedCount` = final count on
  success, 0 otherwise. Array imports record the same fields with array-derived
  counts.

## 23. Remaining Limitations

   on a live GoldenBride profile are UNKNOWN.

   fixed 15:40 mock transaction; fails when the detected shift is not `day`.
   Not caused by this EPIC and not modified.
3. **Root `src/companion` typecheck noise is pre-existing** (Section 19): the
   repo `typecheck` gate does not cover the root tree; a scoped check confirms
   this EPIC adds no new errors.

   and fails on cyclic values. Collections are plain JSON profile data, so this
   is acceptable; documented.
5. **Unknown other container shapes**: only keyed object and array are
   supported; any other real shape (e.g., array with string-key metadata,
   sparse arrays) is UNKNOWN and intentionally not implemented.
6. `npm test` does not exist in the repo (Section 19); harnesses are the test
   suite.
